# Gemini CLI — практики работы ИИ-агента с кодом

Источник: https://thecode.media/gemini-cli-ustanovka-nastrojka-claude-code/  
Обновлено в статье: 21 октября 2026 года.

## Ключевые идеи
Статья описывает Gemini CLI — терминального агентного клиента Google с открытым исходным кодом (Apache 2.0). Сам клиент работает локально, но модель вызывается через облачный сервис; это не локальная LLM.

Полезные практики для Jarvis и других репозиториев:
- Проектный файл инструкций (GEMINI.md; у других агентов — соответствующий файл правил): архитектура, команды сборки, тесты, запреты и критерии готовности.
- Перед задачей — чистое/зафиксированное состояние Git; после — обязательный просмотр diff и результатов тестов.
- Checkpointing и откат изменений агента.
- Policy engine и запрос подтверждения для потенциально опасных действий, в том числе shell/Git.
- MCP для контролируемого подключения внешних инструментов.
- Исключение секретов и больших/ненужных каталогов из контекста; секреты хранить вне рабочей папки.
- Проверяемые задачи с конкретными критериями результата, а не расплывчатые поручения.

## Применение
Эти практики хорошо сочетаются с уже выбранным подходом Jarvis: отдельные ветки, атомарные изменения, тесты, логи и rollback. Можно перенести в единый файл правил для участников разработки и стандартизировать процесс проверки PR.

## Ограничения и оговорки
- Gemini CLI — инструмент разработки, а не компонент для встраивания в Android-приложение.
- Для работы с моделью требуется облачная авторизация: API key, Vertex AI или корпоративный Code Assist. Установка CLI бесплатна, но использование модели может тарифицироваться и ограничиваться квотами.
- В статье указано, что потребительский вход через Google для Gemini CLI прекращён 18 июня 2026 года; условия доступа и лимиты нужно проверять по актуальной документации Google.
- Не выдавать агенту неограниченный доступ к репозиториям, секретам, shell-командам и удалённым операциям.
