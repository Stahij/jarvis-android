# Подборка ИИ-репозиториев GitHub — Habr

Источник: https://habr.com/ru/amp/publications/1075078/  
Заголовок: «100 лучших ИИ-репозиториев на GitHub в 2026 году. От ИИ-агентов до генерации видео».

## Общая оценка
Это обзорный каталог из 100 проектов, а не технический аудит. Числа звёзд и характеристики приведены по статье и могут меняться. Не следует выбирать инструмент только по популярности: перед внедрением проверить активность репозитория, лицензию, безопасность, требования и совместимость.

## Наиболее интересные кандидаты для наших проектов

### Jarvis — локальный ассистент и база знаний
- **OpenClaw** — https://github.com/openclaw/openclaw — персональный агент с подключением к чатам, моделям и инструментам. Изучить архитектуру и модель разрешений; не переносить без проверки безопасности.
- **Mem0** — https://github.com/mem0ai/mem0 — слой долговременной памяти. Сравнить с собственной моделью памяти Jarvis; отдельно оценить приватность и хранение пользовательских данных.
- **RAGFlow** — https://github.com/infiniflow/ragflow — RAG и поиск по документам. Кандидат для будущей локальной базы знаний, но проверить ресурсоёмкость.
- **Docling** — https://github.com/docling-project/docling — извлечение структуры из PDF, DOCX, PPTX и других документов; полезно для импорта материалов.
- **PageIndex** — https://github.com/VectifyAI/PageIndex — поиск по структуре длинных документов; сравнить с обычным RAG.
- **LocalAI** — https://github.com/mudler/LocalAI — локальный сервер моделей и мультимодальных задач. Изучить как альтернативный backend; не считать готовым Android-движком.
- **PrivateGPT** — https://github.com/zylon-ai/private-gpt — приватные ИИ-приложения и поиск по документам на локальных моделях. Возможный источник архитектурных идей.

### Разработка Jarvis и остальных репозиториев
- **Superpowers** — https://github.com/obra/superpowers — рабочие навыки и процесс для агента: планирование, тесты и последовательная реализация. Хорошо сочетается с требованием сначала планировать, затем менять код.
- **OpenSpec** — https://github.com/Fission-AI/OpenSpec — спецификации изменений до начала реализации. Может помочь фиксировать требования и критерии приёмки.
- **Spec Kit** — https://github.com/github/spec-kit — разработка через спецификации и планы.
- **Daytona** — https://github.com/daytonaio/daytona — изолированные среды выполнения кода агентов; изучить как модель песочницы.
- **Goose** — https://github.com/aaif-goose/goose — терминальный агент с поддержкой разных LLM, команд и тестов.
- **Headroom** — https://github.com/headroomlabs-ai/headroom — сжатие контекста для уменьшения расхода токенов.
- **LangGraph** — https://github.com/langchain-ai/langgraph — сценарии агентов с состоянием, ветвлением и восстановлением после ошибок.
- **CrewAI** — https://github.com/crewAIInc/crewAI — координация агентов с разными ролями.
- **Awesome MCP Servers** — https://github.com/punkpeye/awesome-mcp-servers — каталог MCP-интеграций; проверять каждый сервер отдельно.
- **Firecrawl** — https://github.com/firecrawl/firecrawl — извлечение веб-данных для поиска и наполнения базы знаний.

### Kingdoms: Crusader
- **Nakama** уже сохранён отдельно (см. 005-nakama-game-backend.md); он не является частью этой подборки Habr как новая рекомендация.
- **Supabase** — https://github.com/supabase/supabase — backend с PostgreSQL, авторизацией, файлами и API; сравнить с Nakama только для подходящих задач, не считать прямой заменой игрового authoritative-сервера.
- **Meilisearch** — https://github.com/meilisearch/meilisearch — быстрый поиск по игровому каталогу, справочнику и данным.
- **ClickHouse** — https://github.com/ClickHouse/ClickHouse — аналитика больших потоков событий; вероятно избыточен для раннего прототипа.

### FamilyCore
- **n8n** — https://github.com/n8n-io/n8n — автоматизация связей между сервисами; возможен для внутренних интеграций, не как ядро приложения.
- **Supabase** — см. выше: потенциальный backend, но отдельно оценить требования offline-first, синхронизацию, безопасность и владение данными.
- **Frigate** — https://github.com/blakeblackshear/frigate — локальное видеонаблюдение с распознаванием объектов; отдельное направление умного дома, не обязательная часть FamilyCore.

## Приоритет для последующего изучения
1. Superpowers + OpenSpec — дисциплина разработки, тестирования и контроля изменений.
2. Docling + RAGFlow или PageIndex — импорт и поиск по исследовательским документам для Jarvis.
3. Mem0 — сравнение вариантов долговременной памяти.
4. Daytona — безопасная изоляция команд и кода ИИ-агентов.
5. Nakama и Supabase — отдельное сравнение backend-архитектур для Kingdoms.

## Предостережения
- Большинство перечисленных инструментов — серверные или настольные проекты; они не предназначены для прямой установки на Android.
- Локальная модель и облачный агент — разные вещи: наличие open-source кода не означает, что модель работает без API или мощного оборудования.
- Не добавлять зависимости в Jarvis, FamilyCore или Kingdoms только на основании этой статьи.
- Перед использованием проверить лицензию, состояние проекта, уязвимости, требования к ресурсам, обработку данных и стоимость инфраструктуры.
